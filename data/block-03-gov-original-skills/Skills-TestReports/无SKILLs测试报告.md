## 横向分析

### 失分模式统计

| 失分原因 | 出现次数 | 涉及题目 |
|----------|----------|----------|
| **未标注"草稿-待审核"** | 5次 | F2, E3, E4, C1, C2 |
| **写入路径错误**（notices/outbox替代drafts/） | 2次 | F2, E3 |
| **未标注"AI辅助-待人工核对"** | 3次 | F1, F4, F7 |
| **编号格式偏离台账体系** | 2次 | F1, F4 |
| **追加写入vs新建独立文件** | 1次 | F4 |
| **安全边界（权限/密级/确认项）** | 3次 | F5, F6, E3 |

### 根本原因

最大问题不是"不知道"，而是**不标注**。在没有SKILLs的情况下：
- 对"草稿/待审核/AI辅助"标注的重要性缺乏系统性意识，表现为偶发遗漏
- 对写入路径的敏感度不够——outbox vs drafts、notices vs drafts 的选择不一致
- 政务编号体系的遵循有时凭直觉而非标准模板
- **但领域知识本身并未严重缺失**：文种判断、密级标注、紧急分级、科室分工等核心判断基本准确

### 与测试方案预估的对比

测试方案预估无SKILLs得分区间为 **58-88/168**，实际得分 **146/168**。

超出预估上限的原因：
1. **底层模型能力强**（deepseek-v4-pro），本身具备较强的中文政务理解能力
2. **方案低估了通用大模型的政务知识储备**——在15种法定文种、密级标准、公文格式等基础知识领域，大模型本就有较好表现
3. 方案预期"不会生成收文编号/归档编号"，但实际中模型能自主生成，只是格式一致性不够
4. 方案预期"简单摘要，不写入文件"，但实际上模型会主动操作文件系统并生成结构化输出
